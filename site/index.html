DA User Guide

DA (short for Digital Archive) puts your photos and scanned documents in order. You copy them into one folder, and DA:

  • sets exact duplicates aside, so you keep one copy of each photo,
  • works out when each photo was taken, and renames it by that date (photo_19980704_101500_ab12.jpg was taken on 4 July 1998 at 10:15:00),
  • files it in a folder for its year and month (photos\organized\1998\1998-07\).

DA never deletes anything. It asks before it moves anything, and it keeps a record of every change, so every step can be checked and most can be undone.

DA runs on Windows 10 and 11.

Words you'll see

Word What it means
Archive A folder DA looks after, for example D:\jane-archive-199x. You can have as many as you like, for example one for each person and each decade.
Intake The folder inside an archive where you put new photos and documents: intake\. DA takes them from here.
Organized Where DA files them: photos\organized\ and documents\organized\, one folder per year and month.
Duplicate An exact copy of a photo, byte for byte. DA keeps one and moves the others to _duplicates-holding\.
Sidecar A small note DA keeps next to each file, named like the file plus .meta.json. It holds the date DA found, a fingerprint of the file, and any tags. Leave sidecars where they are.
Terminal A window where you type commands. Windows calls it PowerShell or Terminal. DA's menu runs in one.
Command Something you type in the terminal, like da status, then press Enter.

Getting started

1. Get DA

  • Download DA.exe (the latest version), or get the file from whoever set DA up for you (for example on a USB stick).
  • Your browser may ask whether to keep the file. Choose Keep.

2. Install it (once per computer)

  1. Open File Explorer and go to the folder with DA.exe (usually Downloads).
  2. Click in the address bar at the top of the window, type powershell, and press Enter. A terminal window opens in that folder.
  3. Type this and press Enter: powershell .\DA.exe install
  4. If Windows shows "Windows protected your PC", click More info, then Run anyway.
  5. If it says Long paths are off and asks Turn long paths on now?, press Enter (yes), then click Yes when Windows asks for permission. See Long paths for why.
  6. Close the terminal window. From now on, da works in any new terminal window.

DA is now at C:\Scripts\DA\DA.exe. To update DA later, download the new DA.exe and do these steps again; your archives aren't touched.

Long paths

Windows normally refuses a file path of 260 characters or more (the folder names plus the file name). Files copied from deep folders, like intake\docs\from-old-pc\users\jane\school\2022\course\..., can get that long, and setting copies aside (into _duplicates-holding\<date>\...) adds about 30 more. Windows has a setting that lifts the limit, long paths, and DA works with it.

  • da install checks it and offers to turn it on. Windows asks for permission (you need to be an administrator of the computer). It takes effect in new windows.
  • While it's off, DA skips a file whose new path would be too long, carries on with the rest, and says so: path too long for Windows. Turn it on and run again; the skipped files are done then.
  • To turn it on by hand: right-click Terminal (or Windows PowerShell), choose Run as administrator, and type: powershell New-ItemProperty -Path HKLM:\SYSTEM\CurrentControlSet\Control\FileSystem -Name LongPathsEnabled -Value 1 -PropertyType DWORD -Force

Windows won't run DA.exe? If you see "an application control policy has blocked this file", or Windows Security keeps warning about DA.exe, your computer has Smart App Control turned on. It only runs programs that are digitally signed, and DA.exe isn't. Don't turn your protection off: install DA with Python instead. It takes about ten minutes, once.

Install DA with Python (if Windows blocks DA.exe)

What's Python? A free, widely used program that runs programs written in the Python language, which DA is. Python itself is signed by the people who make it, so Smart App Control lets it run, and Python runs DA. You don't need to learn any Python: you install it once, type three lines, and then use DA exactly as described in this guide.

A. Install Python (once per computer)

  1. Go to python.org, point at Downloads, and click the yellow Download Python button. Your browser saves the installer (usually in Downloads).
  2. Open it (double-click it, or click it in the browser's downloads list).
  3. Follow what it shows:
    • If you see a window with an Add python.exe to PATH box at the bottom, tick it, then click Install Now.
    • If a black window asks questions instead (the newer Python install manager), type y and press Enter each time, until it says it's done.
  4. When it's finished, close the installer.
  5. Check it: open a new terminal (press the Windows key, type powershell, press Enter), type this and press Enter: powershell py --version It answers with something like Python 3.14.7. If it says py isn't recognized, close the terminal, open a new one, and try again; if it still isn't, run the installer again.

B. Install DA (once per computer)

In a terminal, type these three lines, pressing Enter after each, and wait for each to finish (the second one downloads DA and the pieces it needs; it takes a minute or two and prints a lot):

py -m venv C:\Scripts\DA\python
C:\Scripts\DA\python\Scripts\python.exe -m pip install -r https://da.gamenightbymike.com/python/requirements.txt
C:\Scripts\DA\python\Scripts\python.exe -m mindit install

What they do: 1. Make a private copy of Python just for DA, in C:\Scripts\DA\python. Nothing else on your computer is changed. 2. Download DA (from this website) and what it needs into that copy. 3. Set up the da command and update every archive's Open DA.cmd to use it. (If an old DA.exe is in C:\Scripts\DA, it's renamed DA.exe.off, so it doesn't get in the way.) It also offers to turn on long paths.

Close the terminal and open a new one. Type da version: it shows DA's version. From here on, everything in this guide works the same: da, Open DA.cmd, the menu.

C. Update DA later: type da update. It downloads the newest version and says which one you have now. If it says it couldn't finish, close every DA window and run it again.

3. Create your first archive (once per archive)

  1. Open a new terminal: press the Windows key, type terminal, press Enter.
  2. Type this (with your own drive, name and years) and press Enter: powershell da setup D:\jane-archive-199x --years 1990-1999

What happens depends on the folder:

  • A new folder: DA creates it, with everything inside it that an archive needs.
  • A folder you've already been copying photos into: DA lists what's there and asks "Make it an archive and move these N items into intake\?". Type y. Everything moves into intake\ with its names unchanged, and the move is written down so it can be undone.
  • A folder that's already an archive: DA asks "Use the existing archive?", keeps its settings, and adds anything missing.

--years 1990-1999 is optional. With it, a photo taken in another decade (say 2005) is left in intake\ and listed for you, so you can move it to the right archive (see da split).

Your archive now looks like this:

D:\jane-archive-199x\
  Open DA.cmd           <- double-click this to open DA in this archive
  da-archive.yaml       <- this archive's settings
  intake\
    photos\             <- put photos here (any subfolders, any names)
    docs\               <- documents: PDF, Word, Excel
    scans\              <- what your scanner saves: PDFs and scanned pictures
  photos\organized\     <- DA files photos here, by year and month
  documents\organized\  <- and documents here
  output\               <- DA's records and reports

4. Open it

Double-click Open DA.cmd in the archive folder. DA's menu opens. That's all you need from here on.

da run is a command you can type. The other "da ..." names stand for a few commands or menu items used together.

Add photos from a phone, camera or memory card

  1. Open the archive's intake folder in File Explorer: D:\jane-archive-199x\intake\photos\.
  2. Make a folder for this batch, named so you'll recognise it, e.g. phone-2024-summer.
  3. Copy the photos into it:
    • iPhone: connect it with its cable and unlock it. Tap Trust if it asks. In File Explorer, open This PC > Apple iPhone > Internal Storage > DCIM and copy the folders you want. (See iPhone HEIC photos about the photo format.)
    • Android phone: connect it, choose File transfer on the phone, then open This PC > (your phone) > Internal storage > DCIM > Camera.
    • Camera or memory card: put the card in the computer (or connect the camera), then open its drive and the DCIM folder.
  4. Copy, don't move, until DA has filed them and you've checked the result.
  5. Then process them.

Any folder names and file names are fine. DA works out the dates itself.

Add scanned documents

  1. Set your scanner to save into D:\jane-archive-199x\intake\scans\ (or copy the files there afterwards).
  2. PDF is best for documents. Pictures (.jpg, .png, .tif) saved in scans\ are treated as documents too, not as photos.
  3. Word and Excel files and other PDFs go in intake\docs\.
  4. Then process them. Documents are filed in documents\organized\ by the date inside them (when they were scanned or created).

da run: file new photos and documents

Menu: 1 Process intake. DA lists the folders in intake\ and how many files each holds:

intake\photos\
 #  folder                         files
 0  process all of intake\photos\  5,081
 1  phone-2024-summer\             1,204
 2  scans-from-grandma\              877
  number: open   0: process   text: filter   .. up   Enter: back
  • Type a number to open that folder. A folder with no folders inside it is processed straight away.
  • Type 0 to process the folder you're in, everything in it.
  • Type some text (e.g. grandma) to show only the folders whose names contain it.
  • Type .. to go up a level, or just press Enter to go back.

DA then works through seven steps. Before each step that changes anything, it asks; type y to go ahead, or n to stop there (nothing after that point changes).

Step What happens Changes files?
1 Index Lists everything in the archive No
2 Hash Fingerprints the photos that could be copies No
3 Duplicates Moves exact copies to _duplicates-holding\ Yes, if you say y
4 Preview Works out each photo's date, new name and folder Only writes the sidecar notes
5 Check Shows how many will be filed, by year, and warns about anything odd No
6 File Renames and moves the photos into organized as the preview planned, then checks each one arrived intact (in place, same size and date, a sample re-read in full), and makes each folder's contact sheet Yes, if you say y
7 Refresh Updates the index No

How long it takes: a few minutes for a few hundred photos; roughly an hour for every 50,000. It's fine to leave it running.

What stays in intake, on purpose: - Photos with no date anywhere (none inside the file, none in its name). See Fix what needs review. - Photos from another decade (with years set). See da split. - Videos (.mov, .mp4): DA doesn't file videos yet. The video half of an iPhone Live Photo is the exception: it's filed with its photo. - Camera raw files (.CR2, .NEF, ...) without a matching JPG. With a matching JPG, the raw file is filed right next to it.

Running it again is always safe. Files already filed aren't touched, and new ones are processed the same way.

From a terminal (handy for leaving a big run going overnight):

da run                                  # all of intake
da run intake\photos\phone-2024-summer  # one folder
da run --yes                            # don't ask; go straight through
da run E:\old-backup                    # a folder outside the archive: DA offers to copy it in first

da report: what's in the archive and what needs you

Menu: 2 Status and 3 What needs review, or da report for a page to print or keep.

A one-page report: type da report (add --open to open it straight away). DA makes a dated PDF, output\jane-archive-199x-report-2026-10-14.pdf, with: - what's filed (photos, documents, space used, the years they span), and how many by year - what's waiting for you (intake, duplicates set aside, notes to review) and the last run - the cameras used, with photo counts, and who took them (from da tag) - the places: how many photos have GPS, a sentence like "This archive includes photos taken in 2 countries (United States, France) and 9 US states (Illinois, Florida, ...)", and the most photographed towns (from da location lookup)

The numbers come from DA's index. If you moved files yourself, use da report --refresh. A second report on the same day replaces the first.

  1. 2 Status: the archive's name and years, what's waiting in intake, what's filed, the last run.

  2. 3 What needs review: what the last run left behind, grouped by reason, with examples:

    • No date (in the file or its name)
    • Taken outside this archive's years
    • File name and camera date disagree (DA used the date in the name)
    • Duplicate inside the folder (left for you to decide)

    The full list is saved as review.csv in that run's folder (DA shows where). It opens in Excel. 3. More detail, from a terminal: powershell da db stats # how many photos and documents, by year da intake status # how far each intake folder has got da validate photos\organized # check what's already filed: names, folders, notes (nothing moves) 4. Every run's record is kept in output\runs\<date-time>-run\: a summary, the duplicate list, and the preview and filing reports, file by file.

If you added or moved files yourself, choose 5 Refresh index first so the numbers are current.

da dashboard: the archive in your browser

Menu: B Dashboard (browser), or type da dashboard.

DA opens a page in your web browser showing the archive as it is now, and keeps it up to date every few seconds. It's handy in a second window while da run works: - Filed: photos, documents, videos and the space they use - Waiting in intake: how many files, folder by folder - Needs review: what the last run left for you, by reason (3 What needs review lists the files) - Happening now: a DA command still working in this archive (in another window, say) - Latest runs and Activity: what DA did, newest first - In the archive: photos by year, the cameras and the places. Counting these takes a while in a very big archive, so DA counts them once when the page opens; Recount counts them again.

The page only reads the archive (nothing changes), and only this computer can open it (its address starts http://127.0.0.1:).

It keeps running in the background, so your terminal (or the menu) is free straight away, and closing the terminal doesn't stop it. Close the browser tab whenever you like; da dashboard (or B) again opens the same dashboard, it doesn't start a second one. To stop it:

da dashboard --stop

Restarting the computer stops it too. To run it in the terminal window instead (until Ctrl+C), use da dashboard --foreground.

The numbers come from DA's index, like the report's: after files were moved by hand, choose 5 Refresh index.

Fix what needs review

Choose 3 What needs review, then for each reason:

  • No date: DA couldn't find when the photo was taken. If you know, even roughly, give it one: see Fix dates (menu D).
  • Outside this archive's years: it belongs in another archive. See da split.
  • Name and camera date disagree: usually the camera's clock was wrong. DA used the date in the name. If that's the wrong one, set the right date (or shift the camera's clock): see Fix dates.
  • Duplicate inside the folder: two identical files. DA leaves both; delete the one you don't want.

Fix dates: photos with no date, or the wrong one

Scans of old prints, photos from a camera whose clock was never set, files that lost their date when they were copied: DA can't tell when they were taken, so they wait in intake. You can tell it. A date you give is kept with the photo (in its sidecar) and always wins over the camera and the file name.

The easy way (menu D Fix dates): 1. Choose D. DA lists each intake folder that has photos with no date, one at a time: For each folder, type the date its photos were taken: 1998, 1998-07 or 1998-07-04. scans\album-1 (48, e.g. scan0001.jpg): 1998-07 scans\album-2 (31, e.g. scan0049.jpg): 1999 phone-old (12, e.g. IMG_0003.JPG): 2. Type a date for a folder, press Enter to skip one, or q to stop. 3. DA asks whether to process intake now. Say yes, and they're filed by the dates you gave.

Dates you can type:

You know Type Filed under
The day 1998-07-04 1998\1998-07\photo_19980704_000000_xxxx.jpg
The day and time 1998-07-04 14:30 1998\1998-07\photo_19980704_143000_xxxx.jpg
The month 1998-07 1998\1998-07\ (as the 1st)
Only the year 1998 1998\1998-01\ (January); a month is better if you know it

From a terminal (also for photos already filed): - See which photos have no date: da date list (or da date list intake\scans). - Give a folder (or photos) a date: da date set intake\scans\album-1 --date 1998-07. - A camera's clock was off (an hour after a time change, or a year that was never set): shift all its photos by the same amount: da date shift intake\phone-old --by +1h (or -1y, +2d, -30m, +3mo). - Changed your mind? da date clear <photos or folder>: the photo's own date counts again.

For photos already in organized, DA then says how to move them to match: da validate "<their folder>" --mode repair renames and moves them by the new date.

Duplicates: put back or delete

Exact copies are moved to _duplicates-holding\<date>\ in the archive, in the same folders they came from.

  • Put them back: 4 Undo last set-aside. Or, for an earlier run, from a terminal: da intake undo "<run folder>\set-aside-moved.csv".
  • Delete them to free the space, once you're happy with the result: delete the _duplicates-holding folder. Every file in it is an exact copy of one that was kept.

da split: move files to the right decade's archive

An archive with years set (e.g. 1990-1999) only files photos taken in those years. One taken in another decade stays in intake, listed under 3 What needs review as "Taken outside this archive's years". da split moves those to the archive for their decade. You don't type the years: each archive's own years setting decides.

  1. See where they belong. In the archive whose intake holds them (e.g. D:\jane-archive-199x), type da split. DA works out each file's date the same way da run does and says: 14 files in intake were taken outside 1990-1999. 11 belong in jane-archive-200x (2000-2009): da split --to "D:\jane-archive-200x" 3 from the 1980s have no archive on this PC yet. Make one: da setup <folder> --years 1980-1989
  2. No archive for a decade yet? Make one: da setup D:\jane-archive-198x --years 1980-1989.
  3. Move them: da split --to D:\jane-archive-200x. DA lists what will move and asks first. Each photo goes with its sidecar, raw file and Live Photo video into the other archive's intake\photos\from-jane-archive-199x\, keeping the folders it was in. Documents go to its intake\docs\. A file whose name is already there stays put.
  4. File them there: open the other archive (its Open DA.cmd, or 6 Switch archive) and choose 1 Process intake.

Good to know: - Changed your mind? da split prints an Undo line: da intake undo "<the file it names>" brings everything back. It works between drives too. - Only some years: da split --to D:\jane-archive-200x --years 2000-2004. - An archive that takes any year (no years:) has nothing "outside" it. To move some photos anyway, give --years. - Files with no sure date stay in intake. Fix their dates first (see Fix what needs review), then run da split again. - Two archives taking the same years: da split says so; the first one on this PC's list gets them unless you say which with --to.

Split filed files too: --organized

da split --organized does the same for photos, videos and documents already filed in organized. Use it to split a big archive that takes any year into the archives for each decade:

da split --organized                                    # see where they all belong (nothing moves)
da split --organized --to D:\jane-archive-200x          # move them (asks first)
da split --organized --to D:\jane-archive-200x --years 2000-2004    # a few years at a time
  • DA finds them by the date in its index (it refreshes the index first), so it's quick even on a big archive.
  • Where they go: when both archives name and folder files the same way (see N Naming), straight into the other archive's organized, in the same folders (location folders too). Otherwise, or when a file with that name is already there, into its intake\photos\from-<this archive>\, to be filed there with 1 Process intake. DA says how many go each way.
  • Each file goes with its sidecar, raw file and Live Photo video; folders it leaves empty are removed, and the contact sheets of both archives are made again (quickly: their thumbnails are kept). The other archive's index is updated straight away.
  • Files with no date stay. Undo: the line DA prints; then 5 Refresh index in both archives.

da find: search the archive

DA keeps an index of every file: its name, folder, date and tags. Choose 5 Refresh index first if anything changed, then in a terminal in the archive:

  • Everything from one month (by the folder it's filed in): powershell da db query "SELECT file_name, folder FROM files WHERE area='photos' AND folder LIKE '2010\2010-07%'"
  • By name: da db query "SELECT path, file_name FROM files WHERE file_name LIKE '%0704%'". To find a file by its original path or name after DA moved or renamed it, search source_path: powershell da db query "SELECT path, area, folder, file_name, source_path FROM files WHERE source_path LIKE '%7a376dda4c8afe76-video.MOV%'"
  • Documents: use area='documents' instead of area='photos'. Other area values are intake and holding.
  • By indexed tags, date, and GPS: tags is stored as a JSON list, so include the quotes around the tag when searching it with SQLite's json_each: powershell da db query "SELECT f.path, f.captured_at, f.tags FROM files AS f, json_each(f.tags) AS tag WHERE lower(tag.value) = 'beach' AND f.gps_present = 1"
  • By place and date range: captured_at is usually ISO date/time text; city and country_code come from location metadata: powershell da db query "SELECT path, captured_at, city, country_code FROM files WHERE city = 'Springfield' AND captured_at LIKE '2010-07%'"

The index's main table is files. These are all its columns:

Column What it contains
id Internal row number.
path File's current full path; use this to locate it now.
area Indexed tree: photos, documents, intake, or holding.
folder Folder relative to its area root (empty for the root itself).
file_name Current filename, including extension.
source_path Original path recorded in the sidecar, when available.
module Metadata module, commonly photoit or scanit.
media_type Kind of file: photo, video, document, raw, or other.
extension Lowercase extension, such as .jpg or .pdf.
size_bytes Current file size in bytes.
modified_at Current file modification time.
sha256 Recorded SHA-256 content hash, when available.
sidecar_path Full path to its .meta.json sidecar, when one was found.
sidecar_schema_version Sidecar format version, when present.
captured_at Capture/document date from metadata, or a date parsed from a DA filename.
tags Tags from metadata as a JSON list, or NULL when there are no tags.
gps_present 1 if GPS metadata was found, otherwise 0.
city City from location metadata, when available.
state_code State or region code from location metadata, when available.
country_code Country code from location metadata, when available.
title Location-group title, when set.
validation_status ok or problems after validation; NULL if not recorded.
validation_problem_count Number of validation problems recorded.
hash_status Hash/quarantine status from metadata, when available.
duplicate_status Duplicate status from metadata, when available.
indexed_at Time this row was last indexed.

Some values are NULL when the sidecar has no corresponding metadata or the file has not been through that workflow. path, file_name, and folder describe its current location; source_path is only as complete as the original sidecar metadata. The index reflects its last build, so refresh it with 5 Refresh index or da db build after files change. da db query accepts read-only SELECT queries; use da findit tags for tag searches when you want full tag matching rather than a SQL text search.

  • By tag or sidecar metadata, use FindIt. Unlike da db query, FindIt reads the .meta.json sidecars in the folder you give it; it searches recursively by default. For example: ```powershell # Find files with the beach tag; -v shows the matching file paths and details. da findit tags photos\organized --require-tag beach --verbose

    Require both tags; exclude anything tagged grandma.

    da findit tags photos\organized -r beach -r family -x grandma -v

    Find July 2010 photos that have GPS metadata.

    da findit tags photos\organized --date-prefix 2010-07 --require-gps -v

    Find tagged scanned documents, and ignore results whose files are missing.

    da findit tags documents\organized -r receipt --module scanit --media-type document --file-exists -v `` Repeated-roptions mean **all** those tags must be present; repeated-xoptions exclude a match if it has **any** of those tags. Tag searches include your tags and DA's automatic tags, such asowner:jane,year:2021, andgps. Other useful filters are--name-contains 0704(case-insensitive filename substring) and--no-recursive` (only sidecars directly in that folder). Filters combine, so the result must satisfy every filter you give.

-v prints the matching files and details; without it, tags prints the search summary and match count. To save the full results as JSON, use --output-file matches.json or --write-output (which writes under reports\findit). - See what metadata FindIt can read: da findit summary photos\organized counts sidecars, files with and without tags, missing files, and metadata categories. It does not list individual matches. Add --no-recursive to limit the summary to that folder, or --write-output to save its JSON. The optional --backend sqlite --db-path <database> is only supported by summary; tag searches use the sidecar backend.

Or just browse: every photo is in photos\organized\<year>\<year>-<month>\, in date order, and each folder's _contact-sheet.pdf shows them all on a page or two.

Contact sheets: a folder at a glance

Every folder DA files photos into gets a contact sheet: _contact-sheet.pdf, small pictures of all its photos and videos. Double-click it to see a whole month at once, or print it.

  • Page 1 sums the folder up: how many photos and videos, the days they span, how many have a GPS position, the places, which sidecar versions they have, and a table of the cameras - who used each, how many pictures, which days, and the page its pictures start on.
  • Then a section per camera. Each page is headed with the folder and the camera, and who used it when DA knows (see da tag): 2018-04 Easter (springfield-il) - Apple iPhone 7 / annie.
  • On each picture: its name and the date and time it was taken underneath; GPS in green down its left edge if it has a position; and a small circled number at its top right: the version of its sidecar (2 is current; see Update sidecars).
  • Duplicates in holding: when DA has a matching SHA-256 copy in _duplicates-holding, the photo tile shows how many there are. Extra pages compare the primary with each held copy, with thumbnails, full file locations, sizes, and SHA-256 values.
  • 12 pictures a page (3 across, 4 down), big enough to recognise. For more on a page, use 20 (4 x 5): da contact-sheets <folder> --layout 4x5, or for the whole archive set it in da-archive.yaml: yaml contact_sheets: layout: 4x5

  • Making a sheet is quick: everything but the pictures comes from the sidecars, and each picture's small copy is kept in the archive's .da\thumbs\ folder (about 22 KB each) under its fingerprint. So when a sheet is made again (after a rename, a move into new folders, or new copies in holding), the photos aren't opened again, which is about 3 times faster. You can delete .da\thumbs\ at any time; DA makes them again as needed.

  • It keeps itself up to date. When da run files more photos into a folder, its sheet is made again. If you add, remove or replace photos yourself, Check what's already filed (da validate) makes it again.

  • For folders filed before DA made sheets, or any other folder of photos (even outside an archive), make them yourself; this does every folder inside the one you name: powershell da contact-sheets photos\organized\1998 Add --force to make every sheet again. After da tag (new cameras or owners), a sheet notices and is made again the next time da run or da validate looks at its folder.
  • DA never files, indexes or checks the sheet itself, and deleting one does no harm.

da tag: label photos and documents

A tag is a word attached to a photo (beach, grandma, trip:big-bear), so you can find it later with da find. DA makes some tags for you, and you add your own.

Automatic tags. When DA first files a photo, it notes what the photo says about itself: the camera's maker and model, the lens, the camera's serial number, any owner name the camera recorded, the date and time, and the GPS position if the phone recorded one. From those, da tag makes:

Tag Example From
maker: maker:apple the camera's maker
camera: camera:apple-iphone-12-pro the camera's model
owner: owner:jane who owned that camera (see below)
year: year:2021 when it was taken
gps gps the photo has a GPS position
  1. Make them for the whole archive: in a terminal in the archive, da tag. It asks first, then works through every filed photo (photos filed before DA kept camera details are read once, roughly an hour per 50,000). To do one year or one folder: da tag photos\organized\2021.
  2. Say who owned each camera (most cameras don't record it): da tag --cameras lists every camera found, with how many photos it took and in which years, then asks about each one with no owner yet: Who used each camera? Type a name, or press Enter to skip. Apple iPhone 7 Plus (160 photos, 2019): jane Apple iPhone 8 (13 photos, 2019): Update the owner: tags now? [y/n] (y): DA saves the names in the archive's da-archive.yaml for you (keeping a copy of the old file), and updates the owner: tags straight away. To set one without the questions: da tag --owner "Apple iPhone 8" sam. A camera listed with a serial number (Nikon D90 #3012345) is that one camera body; without one, every camera of that model.

Your own tags go on one photo, several, or every file in a folder (documents too). Name the files or folders first, then the tags:

da tag photos\organized\2021\2021-06 beach "big bear"
da tag photos\organized\2021\2021-06\photo_20210601_100000_ab12.heic grandma
da tag photos\organized\2021\2021-06 --remove beach

Tags are kept in lower case, with spaces as - (big-bear). Making the automatic tags again never changes yours.

Pictures with text in them (receipts, screenshots, photos of letters or forms): da tag ocr reads the text in each picture of a folder, using Windows' own text reader (nothing to install). It sorts them in three: - document: mostly text (20 words or more, covering a good part of the picture), like a receipt, a letter or a screenshot. Tagged text and document. - text: a few words, like a sign or a T-shirt. Tagged text. - none: no readable words.

Name a folder (a month, a year, or a folder in intake); it reads about 2 to 4 pictures a second:

da tag ocr photos\organized\2021                    # a preview: what it finds, nothing changes
da tag ocr photos\organized\2021 --tag-only         # tag them
da tag ocr photos\organized\2021 --tag-and-move     # tag them, and move the documents
  • --tag-and-move asks first, then moves each document picture, with its sidecar, to documents\organized\<year>\<year-month> with a document's name. One in intake goes to the documents intake folder (intake\docs), for 1 Process intake to file. A picture with no date stays where it is (tagged).
  • Every run writes ocr-results.csv in output\runs\<date-time>-ocr\: each picture, what it held, how many words, what was done, and the start of its text. It opens in Excel.
  • The text is kept in the picture's sidecar (ocr block). A picture already read is skipped next time (--again reads it again), and what a preview read is kept, so --tag-only afterwards is quick.
  • Undo the moves: DA prints the line, da intake undo "<…\ocr-moved.csv>".
  • Find them: da findit tags photos\organized -r document -v.

Switch between archives

  • 6 Switch archive in the menu lists every archive on this computer. Type its number.
  • Or double-click that archive's Open DA.cmd.
  • Or in a terminal: da archives lists them, and da archives --open 2 opens number 2.

Videos

Put videos in intake with your photos (intake\photos\...). 1 Process intake files them the same way: by when they were recorded, into that month's folder, next to the photos from the same days:

photos\organized\2021\2021-06\photo_20210601_090000_ab12.jpg
photos\organized\2021\2021-06\video_20210601_100000_cd34.mov
  • Which videos: .mov, .mp4, .m4v, .3gp, .avi, .mpg, .mpeg, .mts, .m2ts, .wmv, .mkv, .webm.
  • The date comes from the video file itself: phones and most cameras record it inside. DA reads it without any extra programs. A date in the file name (VID 00000-20091016-2017.3gp) is used too.
  • Videos with no date inside (many old .mpg, .wmv and some .avi) wait in intake under 3 What needs review, like photos with no date. Give them one with D Fix dates (or da date set <video or folder> --date 2006-06), then process intake again.

  • The short video of a Live Photo isn't filed on its own: it goes with its photo (next section).

iPhone Live Photos (.MOV files)

An iPhone Live Photo is two files with the same name: the photo (IMG_1234.HEIC or .JPG) and a 2-3 second video (IMG_1234.MOV).

  • DA keeps the pair together. When it files the photo, the video goes with it, renamed to match: photo_20210601_100000_ab12.heic and photo_20210601_100000_ab12.mov, side by side.
  • Videos left behind by an earlier run (filed before DA did this, or copied in after their photo was filed) can be found and put beside their photo. In a terminal, in the archive: powershell da pair-movies # shows what it found; nothing moves da pair-movies --apply # moves them DA matches each video with the photo that was filed from the same place under the same name. It lists what it moved, and da intake undo "<the file it names>" puts them back. A video whose photo hasn't been filed yet is left alone; file the photo first.
  • Other videos (not part of a Live Photo) stay in intake: DA doesn't file videos yet.
  • Don't want Live Photos? On the iPhone, turn off Live (the round icon at the top of the camera) before taking photos.

iPhone HEIC photos

iPhones save photos as HEIC (IMG_1234.HEIC): the same quality as JPG in about half the space.

  • DA files HEIC photos like any other, using the date the iPhone stored in them.
  • To see them on Windows, install the free HEIF Image Extensions from the Microsoft Store (open the Microsoft Store app and search for HEIF).
  • To make JPG copies (for sharing, or for a program that can't open HEIC): powershell da heic-to-jpg photos\organized\2021\2021-06 The copies go in a new folder next to it (2021-06-jpg), with the same date taken; add --out D:\to-share to put them somewhere else. The HEIC originals stay where they are. Running it again only converts photos that are new or changed.
  • To get JPGs from the iPhone instead, on the iPhone open Settings > Photos and, under Transfer to Mac or PC, choose Automatic. The iPhone then converts photos to JPG as they're copied. (Keep Originals copies the HEIC files.)
  • To find the HEIC files in the archive: da db query "SELECT path FROM files WHERE extension='.heic'".

Edit an archive's settings (da-archive.yaml)

  3. Change what you need. Keep the spaces at the start of each line exactly as they are; they matter. Use DA on another computer

An archive is just a folder, so it can live on a USB drive and move between computers.

  1. Install DA on the other computer.
  2. Plug in the drive and double-click the archive's Open DA.cmd. It works whatever drive letter Windows gives the drive.
  3. Each computer keeps its own list of archives for 6 Switch archive. Opening an archive once with its Open DA.cmd adds it to that computer's list.

Merge two copies of an archive

Two copies of the same archive on two drives (say D:\jane-archive-201x and E:\jane-archive-201x) can drift apart: photos added to one, not the other. da merge makes one of them whole.

  1. Open the one to keep (its Open DA.cmd), the one that should end up with everything.
  2. See what it would copy: da merge --from E:\jane-archive-201x. DA indexes this archive, compares the other one file by file (by content, not by name), and says: 48,210 files in jane-archive-201x: 47,903 already here. Copy 307 files (2.1 GB) into jane-archive-201x: 291 to the same folder and name here 16 to intake\...\from-jane-archive-201x (their intake; da run files them)
  3. Press Enter (or add --yes) to copy them. Each file comes with its sidecar.
  4. If some went to intake, choose 1 Process intake to file them.

Good to know: - The other archive is never changed. DA only reads it. When you're happy with the merge, you can keep it as a backup or delete it. - Duplicates aren't copied. A photo this archive already has, under any name or in any folder, is skipped. - Where copies go: a filed photo goes to the same YYYY\YYYY-MM\ folder and name it had there (location folders too). It goes to intake\photos\from-<other archive>\ instead, for da run to file, when it's from a year outside this archive's years, when a different photo already has that name here, or when the two archives name files differently. - Changed your mind? DA prints an Undo line: da intake undo "<the file it names>" removes the copies again (only copies that haven't changed since). - DA checks there's room on the drive first.

Back up an archive

Everything about an archive is inside its folder: the photos, the documents, the settings, the sidecar notes and the records. To back it up, copy the whole archive folder to another drive (File Explorer: right-click the folder > Copy, open the backup drive, Paste).

  • _duplicates-holding\ only holds copies; you can leave it out.
  • The .da\ folder holds DA's index. It's fine to copy it, and DA can rebuild it if it's missing (5 Refresh index).

Delete an archive you no longer need

After its photos have gone to other archives (with da split --organized or merge), delete the old archive with DA, which makes sure nothing is lost first. Open a terminal outside that archive (or another archive's Open DA.cmd), then:

da archives delete D:\jane-archive-all
  1. DA checks every photo, video, document and raw file in it (organized, intake and _duplicates-holding) by its fingerprint, against the other archives on this computer. A backup drive counts too: --also F:\backup. It writes delete-check-<name>-<date-time>.csv: each file and where its copy is.
  2. If any file exists only there, it stops, lists the first few, and deletes nothing. Move them first (da split --organized, or da merge --from in the archive to keep), then run it again.
  3. If everything is elsewhere, it asks you to type the archive's name, then sends the whole folder to the Recycle Bin, and takes it off this computer's list. If the folder is too big for the Recycle Bin, Windows asks before deleting it for good: answer No to keep it.
  • Only on a computer's own drives: a USB or network drive has no Recycle Bin, so DA only checks there; delete it in File Explorer yourself.
  • da archives delete D:\jane-archive-all --forget only takes it off this computer's list; its files stay.

Check what's already filed

da validate photos\organized
da validate documents\organized\2010

This checks names, folders and sidecar notes, and finds duplicates inside that folder. It's a check only: nothing moves (it just adds any missing sidecar notes, and remakes any contact sheet whose folder has changed). The report is saved in output\validateit\.

To fix what it found in organized (wrong names, a photo in the wrong month), add --mode repair. On intake, or on a folder outside the archive, repair stops and tells you to use da run instead, which sets duplicates aside first.

Update sidecars (the .meta.json files)

Beside every file DA keeps a small sidecar, photo_20210601_100000_ab12.jpg.meta.json, with what it knows about the file: when it was taken, its fingerprint, its tags, its place. Sidecars made by older versions of DA (or its predecessor) are laid out the old way, with leftover fields. They still work, but they're cluttered.

  1. Choose J Update sidecars (or type da sidecar upgrade). DA reads every sidecar in the archive and says how many are out of date, and what would change: 143,021 sidecars: 35,810 up to date (schema 2), 107,211 older. 107,211 schema 1 -> 2 107,211 empty scanit block left out 80,412 old fields at the top moved into their blocks
  2. Press Enter to update them. Nothing is lost: old values that differ from the current ones are kept under legacy. Your tags, dates, places and titles stay as they are, and the photos themselves aren't touched.
  3. A copy of every sidecar it changed is kept in output\runs\<date-time>-sidecars\backup\. To put them back: da sidecar upgrade --restore "<that folder>" (DA prints the exact line).

You don't have to do this: any sidecar DA changes for another reason (validating, tagging, a date or a place) is updated at the same time. To do just one folder: da sidecar upgrade photos\organized\2019.

Move folders to another archive by hand

When a few months (or years) belong in another archive and you'd rather move them yourself. Each photo's .meta.json sidecar is in the same folder as the photo, so moving whole folders keeps them together.

  1. Close DA in both archives (every Open DA.cmd window), and stop the dashboard: da dashboard --stop.
  2. Copy the folder to the same place in the other archive, e.g. from D:\jane-archive-201x\photos\organized\2019\2019-04 to E:\sam-archive-201x\photos\organized\2019\2019-04.     • If the two archives name or folder files differently (see N Naming in each), copy into the other archive's intake\photos\ instead, and file them there with 1 Process intake.
    • A location folder (2019-04 Easter (springfield-il)) moves the same way, next to its month.
  3. Check the copy, in the other archive: powershell da validate photos\organized\2019\2019-04 It should find nothing to fix. In File Explorer, Properties of the old and new folder show the same number of files and size.
  4. Delete the original folder in File Explorer (it goes to the Recycle Bin; keep it there until you've checked everything).
  5. Refresh both indexes: choose 5 Refresh index in each archive (or da db build).
  6. Contact sheets: in the other archive, da contact-sheets photos\organized\2019\2019-04. In the old archive, delete the year folder if it's now empty.
  7. Check again: da rename in the other archive says 0 moved to another folder.
  • Moves you make by hand have no undo log: the Recycle Bin is your way back until you empty it.
  • Copies of those photos set aside in _duplicates-holding stay in the old archive.
  • da split --organized (see da split) does all of this for every file another archive's years take.

Location and GPS workflows

Most phones record where each photo was taken (its GPS position); older cameras usually don't. DA reads the position when it first files a photo (or when you run da tag on photos filed earlier) and keeps it in the photo's sidecar.

Works today

  • See which photos have a position: da tag (reads it from each photo once), then da findit tags photos\organized -r gps -v.
  • Find the ones without: da findit tags photos\organized -x gps -v.
  • Put the position in file names: use {gps_compact} (N39W89) or {gps_lat_dir:2}{gps_lon_dir:2} (N39.78W89.65) in the name pattern; see Config tokens.

Look up where photos were taken

da location lookup turns each photo's position into a town (or city) and state, and tags the photo with it: place:springfield-il, state:il, country:us.

  1. Open a terminal in your archive (double-click Open DA.cmd).
  2. Type da location lookup for all your filed photos, or name a folder: da location lookup photos\organized\2019.
  3. DA says how many photos have a position and how many new places it has to look up, about one a second (1,000 new places: about 17 minutes). Press Enter to start.
  4. When it's done it lists the places it found, with how many photos each.

Good to know: - Photos close together (within about 100 m) share one lookup, and every lookup is remembered in the archive, so running it again later only looks up new photos. Run it after each da run. - Photos filed before DA read camera details need da tag first; DA tells you if none have a position. - No internet? The photos it couldn't look up just wait; run da location lookup again later. da location lookup --offline uses only the places already remembered. - Photos taken at sea or in the wild may have no town; DA says how many.

Then find photos by place: - da findit tags photos\organized -r place:springfield-il -v (by town), -r state:il (by state), -r country:fr (by country). - Or ask the index: da db query "SELECT path FROM files WHERE city = 'Springfield'".

Group a month into location folders

Instead of one big 2019-04 folder, put each outing in its own folder, named by you and by where it was: 2019\2019-04 Easter at grandma's (springfield-il)\.

  1. In the menu choose L Location folders. DA lists the months that have GPS photos; type a number. (Or type da location group 2019-04, or the month's folder, da location group photos\organized\2019\2019-04.)
  2. DA looks up any places it doesn't know yet, then shows the groups: photos taken within 6 hours and about 2 km of the one before belong together, so a day out, or a weekend in one place, is one group. Each line shows how many photos, when, and where: 1 24 photos Sat 20 Apr 10:00 - Sat 20 Apr 16:40 springfield-il (24) 2 9 photos Sat 27 Apr 15:00 chicago-il (9)
  3. Type a title for each group you want a folder for, like Easter at grandma's. Press Enter to leave a group in the month folder. Give two groups the same title to put them in one folder.
  4. DA shows the folder names it will make, using your folder pattern, and asks before it moves anything. Press Enter to go ahead.
  5. The photos move, with their sidecars and any raw files or Live Photo videos, and each new folder gets its contact sheet. DA prints an Undo line: to put everything back, type da intake undo "<the file it names>".

Good to know: - Photos without GPS stay in the month folder, unless you give them a place first. If the month folder ends up empty, DA removes it. - Groups too big or too small? --hours 3 or --km 0.5 makes smaller groups; --hours 12 --km 10 makes bigger ones: da location group photos\organized\2019\2019-04 --hours 3. - da validate and da run leave photos in a location folder of their own month. - New photos later? da run files them in the plain month folder. Choose L on that month again: a group taken at the same time and place as a folder you already made says fits the folder already there, and pressing Enter adds the photos to it (type - to leave them). - Without the menu, give the titles in the command: da location group photos\organized\2019\2019-04 --title "1=Easter at grandma's" --title "2=Zoo". A title that is an existing folder's title adds the photos to that folder.

Rename a location folder

Typed the wrong title, or thought of a better one?

da location rename "photos\organized\2019\2019-04 Easter (springfield-il)" "Easter at grandma's"

DA shows the new name, 2019-04 Easter at grandma's (springfield-il), and asks first. The month and places in the name stay; the title changes in the folder name, in every photo's sidecar, in the index and on the contact sheet. It prints the command that renames it back.

Set a place by hand

For photos with no GPS (an old camera, a scan of a print), or when the looked-up place is wrong:

  • By name: da location set "photos\organized\2019\2019-04\photo_20190420_150000_ab12.jpg" --place "Springfield, IL". DA looks the name up, shows what it found, and asks first. A town and state, or a town and country ("Paris, France"), works best.
  • Same as another photo: --same-as <a photo from that day> copies its place. Nothing is looked up.
  • A whole folder: name the folder instead of a photo.
  • Take it off again: da location set <photos> --clear. The next da location lookup looks the photo up again (if it has GPS).

A place you set is never replaced by a lookup. Photos without GPS that have a place join a group when you group the month, as if taken at that place.

Privacy: looking up places sends each spot's position (rounded to about 100 m, never the photo or its name) to OpenStreetMap's free lookup service, Nominatim. To keep positions on this computer, set lookup: off under location: in da-archive.yaml:

location:
  lookup: off

Change how files are named: N Naming, da rename

Choose N Naming in the menu. It shows each kind's pattern (photos, videos, documents) and the ones used before. Then: - Enter checks every filed file against the patterns, and offers to rename those that don't match. - A number (1 photos, 2 videos, 3 documents) asks for a new pattern for that kind, shows what every file would be called, asks Rename N files?, then Save it in da-archive.yaml?

The same in the terminal:

da rename                                                            # check: what would change (nothing changes)
da rename photos\organized\2019 --pattern "{YYYY}{MM}{DD}_{camera}_{hash:4}"            # try a pattern
da rename --pattern "{YYYY}{MM}{DD}_{camera}_{hash:4}" --kind photo --apply --save      # rename, and keep it

It prints how many would be renamed (with the raw files and Live Photo videos that follow them), how many are already named so, and what to follow up: - conflicts: two files would get the same name; they keep theirs (put {hash} in the pattern). - no sure date / no sidecar: they keep their names; set a date with da date set, or run da validate on the folder, then try again. - had nothing for {owner} (or another token): it was left out of those names.

  • The plan, file by file, is rename-plan.csv in output\runs\<date-time>-rename\ (it opens in Excel).
  • --apply asks, then renames each file with its sidecar, raw file and Live Photo video, updates the index, and remakes the folders' contact sheets.
  • Undo: DA prints the line, da intake undo "<...\rename-moved.csv>"; the old names come back.
  • --save writes the pattern into da-archive.yaml (with --kind), and keeps the earlier ones as notes under it, newest first, so going back is easy: yaml pattern: "{YYYY}{MM}{DD}_{camera}_{hash:4}" # was (2026-10-16): photo_{date_taken:%Y%m%d_%H%M%S}_{hash:4} New files are named by it from then on. A copy of the old file is kept (da-archive.yaml.bak-<date-time>).

  • A token with nothing (no owner, no place) drops its level: with {owner}\{YYYY}, a photo with no known owner goes in organized\2019\. da rename counts them (had nothing for {owner}) and notes each one in the plan, so you can fill them in (da tag --owner, da location lookup) and run it again.
  • Location folders work in any layout (da location group 2019-04 finds the month's photos wherever they are), and stay as they are: a photo grouped into 2019-04 Easter (springfield-il) goes in that folder in place of the pattern's last level (jane\2019\2019-04 Easter (springfield-il)\), or where you put {location} in the pattern. Reference

How DA works out a date

In this order:

  1. A date and time in the file name (2024_07_04_10_15_00.jpg, 20240704_101500.jpg).
  2. The date stored inside the file:
    • photos: the camera's "date taken", including iPhone HEIC photos. A camera whose clock was never set (1 January 1970) doesn't count.
    • PDFs: when the PDF was made (scanned, printed or saved).
    • Word, Excel, PowerPoint: when the document was created.
  3. A date without a time in the name (2010-04-27, or US-style 04-27-2010). If the date inside the file is from that same day, its time is used too.
  4. A month and year in the name (Resume April-2010): the date inside the file, if it's from that month. Otherwise only the month is known, which isn't enough, and the file stays for review.
  5. A year only (Beach 1998.jpg): not enough; it stays for review.

When the name and the date inside disagree, the name wins, and the file is listed for review.

Photos are named photo_YYYYMMDD_HHMMSS_xxxx.jpg and documents doc_YYMMDD_HHMMSS_xxxx.pdf; the last four characters come from the file's fingerprint, so two photos taken in the same second still get different names.

Photo or document?

PDFs and Word, Excel and PowerPoint files are always documents. A picture (.jpg .png .tif .bmp) could be a photo or a scan, so the intake folder decides: in docs\ or scans\ it's a document; anywhere else it's a photo. To decide for a whole run: da run intake\old-scans --kind document.

Which archive a command works on

  1. The one you name: --archive D:\jane-archive-199x (before or after the command).
  2. Otherwise, the archive the folder you name is in.
  3. Otherwise, the archive you're in: the terminal's current folder, or one above it.
